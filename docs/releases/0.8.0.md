# Ledgence 0.8.0 candidate

**0.8.0 is undergoing release qualification.** The current verified public
release remains 0.7.0. These notes describe the candidate's changes since 0.7.0
and do not establish package, image or native-bundle availability.

## Recover approved external writes

`ctx.approved_effect(...)` obtains a durable dispatch grant bound to the exact
approved action. A replacement attempt can look up a result or replay an accepted
local record. An uncertain reply never supplies another grant for the occurrence.
Claims and reported outcomes remain inspectable after execution history expires.
Unresolved handling protects the execution evidence needed for investigation.
[Protected actions](../workflow-approvals.md#protect-an-approved-external-write)
· [Retained evidence](../effect-evidence.md).

## Verify who can inspect and decide

Optional installation credentials distinguish operators, services and workers.
Capabilities separate sensitive inspection, approval decisions, effect assessments
and execution. The CLI, Python client, HTTP API, MCP and Console share this boundary.
Approval acceptance records the verified actor separately from the caller's reviewer
label. Sensitive responses are audited before returning their payloads. Pending
result polling retains authorization without recording an absent payload.
[Instance access](../instance-access.md) · [Operator audit](../operator-audit.md).

Existing operator-trusted installations keep their deployment access boundary.
Enabling credentials is explicit and binds the database to its authority.
Historical decisions preserve their original bytes and do not acquire a verified
actor retroactively.

## Resolve uncertainty without occupying a worker

Operators can record success, record failure or close handling as unknown against
an exact occurrence and revision. Acceptance and audit commit together. A native
wait resumes eligible work once, including when the assessment arrived before
parking. Cancellation preserves evidence without reviving the workflow.

Console can download a frozen, destination-bound command for later reconciliation
through the CLI or Python. MCP requires both explicit `--allow-effect-resolution`
and the `effect_resolve` capability. A later conflicting report remains visible
without rewriting the selected wake.
[Inspect and assess effects](../effect-evidence.md#record-an-operator-assessment).

## Reconcile asynchronous provider operations

Provider operations bind business identity, target, application adapter, pinned
program and finite recovery policy into an approval. The dispatch grant reserves
the business key and optional provider deduplication domain/key atomically.
Identical arguments can still represent different intentional business operations.

Typed reports distinguish unknown, pending, required user action and terminal
outcomes. Bounded read-only checks run on a dedicated queue. Waiting releases the
original worker slot. A lost report reply retries the frozen report without another
lookup. Missing evidence or an expired provider key never authorizes another write.
Every outcome uses a durable ticket and continuation, without a fabricated local
journal result. [Provider contract](../provider-operations.md)
· [Runnable reference adapter](../../examples/provider-recovery/README.md).

Provider adapters remain application code. The platform has no mandatory provider
SDK or hosted service. Ledgence records the reporting worker and approved binding,
not independent proof of an arbitrary provider's state.

## Inspect work in Console

The refreshed light and dark appearances improve contrast and legibility and move
appearance controls into the sidebar. Effects and audit views connect evidence with
its workflow and verified actor. Graph and Trace distinguish native effect waits,
provider waits and provider-check tasks using durable execution relationships.
Deploy matching Console contract **7** server and assets and refresh older tabs.
Workflow runtime protocol **3** remains, with negotiated optional capabilities.
[Console contract](../console.md).

## Plan the upgrade

Stop all writers, preserve the database and immutable program store, run the
explicit migration and restart matching components and connection pools.
Backfill preserves old decision and accepted journal bytes. Historical approved
actions become lookup-only when adopted into protected execution. Existing
ordinary programs do not automatically become provider operations.
[Candidate upgrade guide](../../docs-site/src/content/docs/how-to/upgrade-to-0-8.md)
· [Migration details](../postgres.md#upgrade-from-070-to-development-source).

Independent effect evidence and acceptance records have no automatic expiry.
Execution retention keeps its existing minimum age and cleanup conditions.
Confirmation, a verified assessment or terminal provider knowledge can release the
relevant unresolved hold without deleting evidence or reversing external effects.
The local kit remains operator-trusted and a CLI update does not upgrade a saved
installation. Access and provider policy require explicit configuration.

Local PostgreSQL and ElasticMQ checks cover recovery behavior, including the
provider probe path. They do not establish AWS capacity or externally exactly-once
effects. Restore quarantine must be declared outside the restored database.
Final distribution and performance qualification remain release requirements.
