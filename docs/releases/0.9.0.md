# Ledgence 0.9.0

## Share a provider across workers

A named resource can limit outstanding calls and apply a token-bucket rate policy across programs and queues. Workflow callbacks can checkpoint while they wait. Standalone tasks can declare a resource at submission. Protected provider mutations bind resource admission to the approved, one-shot dispatch grant. Use weighted groups when interactive traffic and a batch share the same provider. Each weight counts offers; the scheduler can lend idle capacity to an eligible group. [Resource admission](../resource-admission.md) · [Weighted offer example](../../docs-site/src/content/docs/how-to/share-resource-offers.md).

## Bound a run across its branches

A root task or workflow can declare a maximum number of authorized calls, a delegation limit and an absolute deadline. Owned children share the remaining allowance. A recorded result can replay without consuming another call. A worker crash after authorization can leave a call charged and its actual usage unknown. Reported and estimated token counts remain distinguishable. Direct application network calls and retries inside provider SDKs are outside these controls. [Run budgets](../run-budgets.md) · [Run the shared-budget example](../../examples/shared-run-budget/README.md).

## Give each queue the capacity it needs

One worker can serve multiple HTTP or SQS-compatible queues with a single concurrency setting. Choose stride or weighted lottery for polling. Updating shares lets busy consumers finish their assignments. A separate PostgreSQL policy can limit concurrent attempts on an individual queue across workers. A lost worker can leave a slot held until cleanup is confirmed. An explicit timeout policy can request a stop and optionally release capacity after a grace period, recording any unconfirmed closure. [Worker poll planning](../../docs-site/src/content/docs/how-to/share-worker-polls.md) · [Queue concurrency](../queue-concurrency.md).

## Operate an installation

Matching Console C14 assets and server expose resource policy revisions, weighted offers, outstanding dispatch sources, queue holds and run budgets. An operator can start from the resource name when a source still occupies capacity after its execution history has been collected. Resource policy changes are revision-bound. Sensitive source reads are audited. The same installation is accessible through the native API, Python client, CLI and MCP. Optional operational metrics use bounded labels. [Console contract](../console.md) · [Metrics](../metrics.md). [Reproduce the resource admission load checks](../resource-load-qualification.md).

Back up the database and immutable programs, stop writers and run the explicit migration before enabling new policies. For a restore, preserve external provider evidence and apply the recovery policy before resuming writes. A missing local row cannot establish that an external operation never happened. [Upgrade from 0.8](../../docs-site/src/content/docs/how-to/upgrade-to-0-9.md) · [PostgreSQL operations](../postgres.md).
