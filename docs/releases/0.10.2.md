# Ledgence 0.10.2 candidate

These notes describe the current 0.10.2 candidate source. The verified public
release remains **0.9.0**; native bundles, containers, packages and the local kit
must each pass publication checks before these notes describe available stable
downloads. Use matching candidate server, worker, Console, CLI and Python
components while evaluating the changes below.

This candidate supersedes the held 0.10.0 and 0.10.1 candidates; their existing
tags and notes remain unchanged. Qualification fixtures now synchronize deadline
triggers and scoped trace collection, removing test timing and observation races.
These corrections do not change runtime contracts or add release capabilities.

- The provider qualification fixture isolates temporary executables from an
  inherited `CARGO_TARGET_DIR`, preserving existing developer build artifacts.

## Follow an execution and reconnect

Tasks and workflows expose bounded, resumable lifecycle history through HTTP,
Python, `task progress`, `workflow progress`, MCP and Console. Save the returned
cursor after processing a complete page and resume from it after a disconnect.
Observation does not resubmit or cancel work. This is committed lifecycle history,
not application milestones, logs or model-token streaming. History has the
execution's retention lifetime: whole-execution retirement returns `NotFound`,
with no independent cursor TTL or automatic reset. [Progress contract](../execution-progress.md)
· [Runnable observer](../../examples/execution-progress/README.md).

## Share immutable execution files

Upload files up to **64 MiB** and pass immutable references between steps in the
same execution root. Inspect metadata separately from explicitly downloading
bytes. Files follow the root's retention, including files produced by its children.
Uploads with uncertain outcomes retain their selection identity for explicit
status, reconciliation or eligible replacement; a timeout does not prove the
write failed. The feature is optional and requires `--artifact-config`, separate
from the program-package store. [Storage, authorization and recovery contract](../execution-artifacts.md)
· [Two-worker example](../../examples/execution-artifacts/README.md).

Filesystem storage supports one orchestrator on a persistent local volume. Its
hidden identity marker, configured `store_id`, objects and matching database are
one recovery set. The optional `s3-artifacts` build uses conditional writes and
checksums; its local RustFS qualification profile does not establish AWS or
arbitrary S3-service qualification. Spools and worker caches are transient.

## Choose an optional framework adapter

Three optional, application-owned profiles use `pydantic-ai-slim==2.66.0`,
`google-adk==2.14.0` with `google-genai==2.34.0`, or
`claude-agent-sdk==0.2.180`. None is a mandatory core or base-helper dependency.
PydanticAI and ADK replay accepted bounded model/read-tool operations. Claude
replays an accepted whole-run result; it does not restore native sessions or
replay individual internal tools. Applications retain ownership of providers,
models, credentials and dependency packaging. [Profiles and limits](../agent-integrations.md)
· [Shared examples](../../examples/framework-integrations/README.md).

Offline SDK and real-worker gates use deterministic providers/transports. They
do not qualify live model providers, a separately installed native Claude CLI,
session restoration or exactly-once external effects.

## Prepare larger application packages explicitly

The negotiated `entries-8192-v1` profile permits **8,192 entries**, including
directories and the manifest, while the legacy profile remains **4,096**.
Compressed, expanded and per-file byte limits remain unchanged. Clients negotiate
before uploading; a package exceeding a legacy peer's limits is rejected before
PUT. Upgrade every eligible worker before publishing larger packages. Compatible
older immutable packages do not require rebuilding merely because Ledgence was
upgraded. Runtime, platform and exact CPython compatibility still apply.
[Publication and mixed-version contract](../program-publication.md#binary-api-and-bounds).

## Upgrade and preserve local state

The artifact migration is `20261110000000_execution_artifacts.sql`. Stop writers,
back up and rehearse on an isolated restore before migrating. Keep the original
instance, authority and scope. Existing credentials do not acquire
`artifact_write`; issue explicitly scoped credentials against the existing
authority rather than initializing a new one. Use Console contract **16** and
matching helpers and clients. [Upgrade from 0.9](../../docs-site/src/content/docs/how-to/upgrade-to-0-10.md)
· [PostgreSQL operations](../postgres.md).

New candidate local kits configure persistent filesystem execution storage and
service-specific shutdown grace periods. The CLI respects the saved Compose
configuration. Installing a newer CLI does not replace existing kits, images,
volumes or schema. Preserve filesystem marker bytes when restoring artifacts,
and populate an empty target before any server first opens it. Old binaries
reject the migrated schema; rollback requires a fresh restored database and
external-effect reconciliation.

Exact candidate qualification, public artifact verification and website
deployment are separate outcomes. See the [release procedure](../releasing.md)
for the required evidence; these notes alone do not establish that a gate passed.
