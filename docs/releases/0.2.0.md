# Ledgence 0.2.0

Ledgence 0.2.0 adds a self-hosted Console, one CLI for platform operations, and
typed Python workflow entrypoints with durable forks. This release changes the
command layout and database startup requirements; read the
[upgrade guide](../upgrading-to-0.2.md) before replacing an existing deployment.

## Self-hosted Console

The Rust orchestrator serves Console assets alongside its API, with no Node
process or hosted account required in production. One server-owned instance
binding connects the UI to the installation's existing tenant/namespace scope.

- Browse one task and workflow history with exact filters, submission-time bounds,
  root/child scope, bounded paging, and an explicit refresh back to live results.
- Inspect attempts, input/output, resource measurements, and recorded workflow
  relationships through Graph and Trace. Graph edges come from durable execution
  relations; they do not infer dependencies from timing or predict future steps.
- Register published immutable programs, inspect exact versions and runtime
  requirements, and submit, rerun, or cancel executions.
- Inspect worker process slots and the age of their observations. A stale report
  does not prove process death or make occupied capacity available.

Console uses contract **4**. Server and assets must match; older development
Explorer cursors must restart from the first page. Native bundles include
Console and retained frontend notices.

## Unified command-line interface

The public executable is now `ledgence`, built from `ledgence-cli`. Its command
groups are `program`, `worker`, `orchestrator`, and `task`. Worker and
orchestrator still run as separate processes.

| Previous command | Replacement |
| --- | --- |
| `ledgence-worker example` | `ledgence program example` |
| `ledgence-worker publish` | `ledgence program publish` |
| `ledgence-worker run` / `connect` | `ledgence worker run` / `connect` |
| `ledgence-orchestrator migrate` / `serve` / `retain` | `ledgence orchestrator migrate` / `serve` / `retain` |

Existing `ledgence task ...` commands remain. Use `ledgence --help`,
`ledgence --version`, and group help for command discovery. The default build
includes OpenTelemetry support; `--features sqs` adds the optional delivery
adapter, and `--all-features` includes all supported integrations. Export and
broker use still require explicit runtime configuration.

## Typed workflows and durable branches

Python programs can register `Workflow(StrEnum)` handlers with
`@workflow.entrypoint(...)` and export `workflow.build()`. A public submission
starts at the default handler; branch and resume decisions address registered
entrypoints. Existing `workflow_context()` controllers and string continuations
remain supported, and workflow runtime protocol **3** is unchanged.

`await ctx.fork(...)` acknowledges atomic branch registration before the parent
continues local work. Each branch has its own workflow identity, checkpoints,
and waits while using the parent's exact immutable program descriptor.
`return ctx.join(...)` saves state, releases the invocation slot, and resumes
when every branch is terminal. Failed and cancelled outcomes require application
handling; joining does not imply fail-fast behavior or exactly-once external
side effects.

## Examples and client improvements

The example catalog now includes typed checkpoint and mixed local/distributed
workflows, Codex and Google ADK support agents with durable review, and a Codex
change-review workflow combining local checks with distributed branches.
Provider integrations remain optional. Their live modes require the documented
provider setup; they are not required to self-host Ledgence.

Python client URL normalization now preserves Unicode host identity using the
same IDNA behavior as its transport, including hosts such as `faß.de`. The
`ledgence.client` and `ledgence.worker` namespaces remain unchanged from 0.1.1.

## Reliability fixes

- Console history can recover live results after browsing multiple pages. Back
  navigation follows actual in-app history and preserves validated list filters
  when reopening or reloading a detail page.
- Valid workflow rejection diagnostics remain readable in Console even when JSON
  escaping expands their stored representation.
- Subprocess workspace cleanup runs off asynchronous runtime threads and retains
  ownership across cancellation.
- CLI endpoint validation occurs before telemetry startup. Disposable integration
  fixtures use their own PostgreSQL databases instead of sharing lifecycle state.

## Distribution and upgrade requirements

Native bundles target **Linux x86_64/glibc**, built and qualified on Ubuntu 24.04,
and **macOS arm64**, with the unified binary, Console, worker helper, Python
client artifacts, checksums, and provenance. Consult each archive's dynamic
library requirements; no other Linux distribution or native target is implied.
CPython, PostgreSQL, brokers, and host libraries are supplied separately.
The client and both Rust API crates use version **0.2.0**.

Stop producers, workers, orchestrators, and other writers; preserve tested
backups; explicitly apply all migrations; and start matching components with a
persistent instance configuration when adopting Console. Headless operation on
an unbound database remains supported without that configuration. Older binaries cannot use the upgraded
schema. Rollback restores a matching pre-upgrade backup and deployment instead
of running older services against the new database.

The historical native 0.1.0 and source/package 0.1.1 releases are unchanged. They
predate Console, typed entrypoints, and durable forks. Ledgence remains MIT
licensed, self-hostable without a mandatory vendor account, and intended for
operator-trusted code. Third-party software retains its own licenses and notices.
