# Ledgence 0.6.1

Ledgence 0.6.1 updates the visual identity and introduces a guided path from
local installation to a first task and workflow, and updates TLS dependencies.
These notes describe the changes relative to 0.6.0.

The [0.6.1 release](https://github.com/Ledgence/ledgence/releases/tag/v0.6.1)
includes matching native bundles, Console, installer, local kit, Linux container
runtimes, Python client and worker helper packages, and Rust API crates. Required
qualification and public download checks completed on **2026-10-20**.
Website deployment is a separate operation.

## Curvature identity

The Curvature symbol appears in Console, the documentation site and portable
example reports. Repository and registry README headers use the matching
wordmark. The [brand kit](../../assets/brand/README.md) includes vector masters,
favicons, profile images and social previews, with usage guidance and required
license notices. Console serves its brand assets locally.

The saved workflow demo retains its original execution evidence. Updating its
presentation does not relabel that run as evidence for new runtime features.

## Installation and first programs

The [installation guide](../installation.md) separates automatic local setup,
direct Docker Compose and compiling the CLI from source. Each route explains
its prerequisites, the matching container runtime and how to reach Console.
Manual native installation and the full source stack remain separate guides.

The [Hello Ledgence examples](../../examples/hello-ledgence/README.md) follow one
continuous lesson: publish a greeting task, call that task from a workflow, then
inspect the resulting executions in Console. The lessons provide complete named
Python files, expected results and explanations of the client, worker helper,
program build target and publication steps. They require no model provider or
API key.

Documentation also clarifies Python application dependencies, Docker and worker
target requirements, parallel tasks and workflow branches, and the difference
between installing a CLI and upgrading an existing saved local stack.

The introductory programs have unit tests, and documentation checks compare the
complete Python snippets with their runnable source files. These checks cover
example behavior and consistency; they do not replace runtime qualification.

## Dependency maintenance

`rustls-webpki 0.103.16` rejects certificate paths containing distrusted emSign
intermediary public keys, addressing
[RUSTSEC-2026-0382](https://rustsec.org/advisories/RUSTSEC-2026-0382).
`webpki-root-certs 1.0.10` removes the emSign ECC Root CA - G3 certificate from
the all-target dependency graph, addressing
[RUSTSEC-2026-0383](https://rustsec.org/advisories/RUSTSEC-2026-0383).
The root-data crate belongs to the WebAssembly TLS path and is not required by
the supported Linux/macOS builds. The validator update applies to native TLS
connections. No advisory exception was introduced.

Console and documentation build dependencies are also updated to patched
versions. Vite's bundled editor-launching utility is corrected for its Windows
development-server path
([GHSA-698v-4r3x-3vcv](https://github.com/advisories/GHSA-698v-4r3x-3vcv)).
These tools build static assets; they are not runtime services deployed with
Console or the documentation site. Existing dependency-license reviews and
notice collection remain required.

## Upgrade and operating scope

There are no new PostgreSQL migrations, public API contracts, or execution
semantics relative to 0.6.0. Console contract **5** and workflow runtime protocol
**3** remain unchanged. The task, workflow, program-publication and recovery
capabilities remain those of the 0.6 release series.

Use matching CLI, services, Console assets and Python helper versions. Updating
the CLI does not replace an existing installation's saved kit or pinned image;
follow the [0.6 upgrade guidance](0.6.0.md#upgrade-and-operating-scope) and retain
normal backups. Existing application program versions remain independent of
the platform version.

Ledgence continues to execute operator-trusted code. This update does not change
delivery guarantees, external-effect semantics or isolation boundaries.
Ledgence-owned code remains MIT; third-party components retain their licenses
and required notices.
