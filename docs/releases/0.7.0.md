# Ledgence 0.7.0

This version adds a cross-workflow approval inbox and inspection of accepted
workflow operations. These notes describe the changes since 0.6.1. Both native bundles, the installer, matching Compose kit, Linux container images, Python packages and Rust API crates were published and verified. [Release artifacts](https://github.com/Ledgence/ledgence/releases/tag/v0.7.0).

## Find requests that need a decision

Open **Approvals** to see requests across workflows in the instance scope,
ordered by earliest deadline. Filter by status, program or **Due before (UTC)**.
Open a request to review its exact effective arguments, approve or reject it, or
go to its recorded wait in the workflow graph. The CLI, Python client, HTTP API
and read-only MCP tool also support discovery. [Approval inbox](../workflow-approvals.md#approval-inbox).

## Inspect the result a workflow accepted

In Graph or Trace, select a local step and open **Inspect durable operation**.
For a model or tool call, the inspector shows its version, effective arguments
and accepted result. For an ordinary step, it shows the input passed to the step.
The recording attempt and timestamp come from the durable journal. A later
attempt can report that it reused the result. [Operation inspection](../agent-recovery.md#inspect-an-accepted-operation).

## Reliability and upgrade

Workflow decisions now fence stale activations and preserve partial resolution
progress when resolving child programs. Other fixes cover independent cache
verification by digest, argument binding for approved operations and program
build input/output directory overlap.

Stop writers before migrating from 0.6.1. The upgrade adds a child resolution
progress table and backfills the approval inbox indexes. Budget maintenance
time according to the number of retained approval requests. The inspector reads
existing journal records directly. [Migration instructions and rehearsal](../postgres.md#upgrade-from-061-to-070).
